## Mobile and migration boundaries

Mobile remains the Rider application. Its public signup deliberately provisions Rider access without an organisation. No new signup marker, Mobile runtime change or EAS build is introduced. Invalid or unrelated Admin provisioning never falls back to that journey.

078 replaces only `guard_employee_auth_insert`, `handle_new_user` and `provision_product`. It reuses the existing durable reservation, adds no ledger/role alias/evaluator/membership writer and performs no data backfill, enum expansion or historical-row rewrite. Existing Rider/Advertiser recipes and explicit external/Staff provisioning remain supported.
