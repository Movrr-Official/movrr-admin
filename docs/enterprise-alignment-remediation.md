## Rollout manifest and dependencies

Do not deploy these files implicitly on push. Admin already disables Vercel deployment for `main`; App now does likewise. Reviewed repository workflows contain CI checks, not an EAS release command. Preserve the separate iOS Preview work and all unrelated Mobile commits.

Apply **full paths** in this order, after explicit rollout approval and a fresh drift/preflight check (`node scripts/inspect-alignment-contracts.cjs --check-baseline`):

1. `movrr-admin/scripts/055_alignment_security.sql`: account predicate, restrictive policies and guarded existing RPCs. Verify the guarded function bodies/signatures against current production first. Policies compose with existing ownership; receipt authorities are excluded.
2. `movrr-mobile/scripts/093_alignment_accessory_custody.sql`: X07 installation/issue transactions. Requires the account guard from step 1. No Mobile binary or OTA is needed.
3. `movrr-admin/scripts/056_alignment_capabilities.sql`: generated projection of existing employee templates; regenerate/check from the release revision.
4. `movrr-admin/scripts/057_alignment_operations.sql`: private operation receipts, incident records, notification jobs and inventory commands. Rehearse persisted incident migration and check duplicate active custody before creating the unique index. Schema or data conflicts must stop rollout, not be repaired by deleting history. New actor/recipient identifiers use canonical subject columns and foreign keys; include these private records in the existing deletion inventory/retention review before activating physical account deletion.
5. `movrr-admin/scripts/058_alignment_reads.sql`: scoped pages/catalog, Wallet snapshot, profile preference transaction and durable community creation/cancellation. Existing callers must switch with the corresponding application revision.
6. `movrr-admin/scripts/059_alignment_impact.sql`: shared active-production impact evidence and daily/lifetime projections. Preserve current methodology until separately approved.
7. Release the matching Admin Platform/dashboard revision, then authenticated web. Keep Shop disabled throughout. Do not run an older SQL snapshot over these definitions.

The migrations do not erase ledger history, earned points, fulfillment, assignment history or identity records. They require coordinated backend/application rollout. Authentication, Wallet, campaigns, rides and operational features must not be released against missing new RPCs. Do not restore unsafe writers as a rollback shortcut: hold the rollout, keep affected controls unavailable and use an approved forward correction. Existing fulfillment obligations and receipt access must remain reachable.
